Environment, quickstart and model reproduction

Start with standard-library checks and a local website preview. The model guide covers original-input reconstruction, required local files and prediction commands. Existing-weight replay has passed; fresh end-to-end training remains unvalidated.

C+ names the final model in this project: RoBERTa with 42 comparison features, averaged across three training seeds.

01

Environment and quickstart

Install Git and Python 3.11 or newer, then clone the repository. These checks and the local website use only the Python standard library. The project environment below keeps any later dependencies separate from your other projects.

git clone https://github.com/Yemyu/product-entity-matching.git
cd product-entity-matching

macOS / Linux

python3 -m venv .venv
.venv/bin/python scripts/public_smoke.py
.venv/bin/python -m http.server 8000 --bind 127.0.0.1

Windows · PowerShell

py -3.11 -m venv .venv
.\.venv\Scripts\python.exe scripts/public_smoke.py
.\.venv\Scripts\python.exe -m http.server 8000 --bind 127.0.0.1

The smoke check prints a JSON report with status passed. Keep the server running and open the local project site below; Ctrl+C stops the server.

Open the local project site

Choose the command block for your operating system. Commands use the interpreter in the project's .venv: .venv/bin/python on macOS/Linux and .\.venv\Scripts\python.exe on Windows. If you downloaded a ZIP, enter the extracted repository folder and start with the environment commands.

Real input preparation and model prediction require locally supplied product data, model snapshots and checkpoints. Follow the linked guide for the GPU environment and working directories; the documented CUDA setup was checked on Windows 11 with an RTX 3060.

02

Check the public code and saved outputs

After setting up the environment above, run these checks from the repository root. They exercise input interfaces, feature calculations and metric arithmetic using synthetic records, and check the stored aggregate results. They require no model download or GPU.

01

Interfaces, saved outputs and file checks

public_smoke.py checks the package and CLI entry points. run_notebook.py runs the English and Chinese executable walkthroughs and compares their saved outputs. verify_public_release.py checks the public file inventory, hashes, local links and result arithmetic. A passed report confirms these code and document checks; it does not run model inference.

macOS / Linux

.venv/bin/python scripts/public_smoke.py
.venv/bin/python scripts/run_notebook.py
.venv/bin/python scripts/verify_public_release.py

Windows · PowerShell

.\.venv\Scripts\python.exe scripts/public_smoke.py
.\.venv\Scripts\python.exe scripts/run_notebook.py
.\.venv\Scripts\python.exe scripts/verify_public_release.py

These command-line interface (CLI) stages connect pair preparation, model training, prediction and evaluation. Model runs require local product inputs, pinned dependencies and model files. The guide gives file formats and full arguments for each stage.

04

Existing-weight replay results

Replay used the original fixed inputs and local model files to prepare inputs and predict with existing weights. Across 20 commands, 23 independently checked result groups matched the saved outputs; the maximum prediction difference was 0.0. No new weights were fitted, and no independent new Walmart–Amazon sample was evaluated.

  • Prepared tokens, 42 features and the fit-only IDF state
  • Fixed MiniLM semantic features and four reference predictions
  • Three-seed predictions and final ensemble probabilities

Replay environment: Windows 11, Python 3.11.16, PyTorch 2.8.0+cu126 and an RTX 3060 laptop. Other GPU platforms have not been validated. The aggregate record is available as fixed-results.json.

05

Original inputs and fresh training

The reconstruct-roles command verifies the original ZIP and restores the four fixed role inputs byte for byte, including native-field missing masks. The recipe contains source positions and hashes without product values or labels. Existing-weight replay requires local snapshots and trusted weights; fresh end-to-end training and independent new Walmart–Amazon sample evaluation remain unvalidated.

The reproduction guide specifies the required files, project environment and command sequence. Keep evaluation labels separate from model input, and use the documented role assignments to reproduce the saved experiment.

07

Local static-page generation

The standard-library generator reads the saved aggregate results, final model configuration, feature order and bilingual page text. It writes eight complete HTML pages and a result CSV. This command generates documentation; it neither fetches product data nor loads a model.

macOS / Linux

.venv/bin/python scripts/build_showcase.py
.venv/bin/python scripts/build_showcase.py --check

Windows · PowerShell

.\.venv\Scripts\python.exe scripts/build_showcase.py
.\.venv\Scripts\python.exe scripts/build_showcase.py --check

The check command generates in memory and compares every generated byte. It does not write files.
