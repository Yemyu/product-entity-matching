Code and reproduction

Environment, quickstart and model reproduction

Start with standard-library checks and a local website preview. For model reproduction, the guides describe source-input reconstruction, required local model files and prediction commands. Existing-weight replay has passed; fresh end-to-end training remains unvalidated.

C+ names the final model in this project: RoBERTa with 42 comparison features, averaged across three training seeds.

01

Environment and quickstart

Install Git and Python 3.11 or newer, then clone the repository. These checks and the local website use only the Python standard library. The project environment below keeps any later dependencies separate from your other projects.

git clone https://github.com/Yemyu/product-entity-matching.git
cd product-entity-matching

macOS / Linux

python3 -m venv .venv
source .venv/bin/activate
python scripts/public_smoke.py
python -m http.server 8000 --bind 127.0.0.1

Windows · PowerShell

py -3 -m venv .venv
.\.venv\Scripts\python.exe scripts/public_smoke.py
.\.venv\Scripts\python.exe -m http.server 8000 --bind 127.0.0.1

The smoke check prints a JSON report with status passed. Keep the server running and open the local project site below; Ctrl+C stops the server.

Open the local project site

The remaining commands use python from the activated macOS/Linux environment. On Windows, replace python with .\.venv\Scripts\python.exe. If you downloaded a ZIP instead of cloning, open its extracted repository folder and start with the environment commands.

To prepare real model inputs or run prediction, supply the product data, model snapshot and checkpoints locally. Install the pinned neural dependencies in a separate project environment; the documented CUDA setup was checked on Windows 11 with an RTX 3060.

Check the public code and saved outputs

After setting up the environment above, run these checks from the repository root. They exercise input interfaces, feature calculations and metric arithmetic using synthetic records, and check the stored aggregate results. They require no model download or GPU.

01

Interfaces, saved outputs and file checks

public_smoke.py checks the package and CLI entry points. run_notebook.py runs the English and Chinese executable walkthroughs and compares their saved outputs. verify_public_release.py checks the public file inventory, hashes, local links and result arithmetic. A passed report confirms these code and document checks; it does not run model inference.

python scripts/public_smoke.py
python scripts/run_notebook.py
python scripts/verify_public_release.py
02

CLI help and synthetic contract tests

The help command shows the explicit preparation, training and prediction entry points. The test suite checks synthetic cases. Passing these tests is separate from reproducing the model experiment.

python scripts/matching.py --help
python scripts/run_tests.py

04

Verified existing-weight preparation and prediction

The public code entry ran 20 commands with original frozen inputs and local model artifacts. 23 independently checked result groups matched the saved outputs; the maximum prediction difference was 0.0. The replay covered input preparation and existing-model predictions. It did not fit new weights or evaluate an independent new Walmart–Amazon sample.

  • Prepared tokens, 42 features and the fit-only IDF state
  • Fixed MiniLM semantic features and four reference predictions
  • Three-seed predictions and final ensemble probabilities

Observed environment: Windows 11, Python 3.11.16, PyTorch 2.8.0+cu126 and an RTX 3060 laptop. Other GPU platforms have not been validated. The aggregate record is available as fixed-results.json.

05

Original inputs and fresh training

The reconstruct-roles command verifies the original ZIP and restores all four role inputs byte for byte, including the original native missing masks. The recipe contains source positions and hashes, with no product values or labels. GPU replay still requires local snapshots and trusted weights. Fresh end-to-end training and independent new Walmart–Amazon sample evaluation have not been validated.

Use locally supplied artifacts under their applicable terms and a project environment. Fit estimates model parameters and IDF; development selects the epoch; calibration selects the cutoff. Evaluation labels remain separate from model input and are not used to choose these settings. The interface checks do not resolve the historical exposure of the saved evaluation pool.

07

Local static-page generation

The standard-library generator reads the saved aggregate results, final model configuration, feature order and bilingual page text. It writes eight complete HTML pages and a result CSV. This command generates documentation; it neither fetches product data nor loads a model.

python scripts/build_showcase.py
python scripts/build_showcase.py --check

The check command generates in memory and compares every generated byte. It does not write files.
