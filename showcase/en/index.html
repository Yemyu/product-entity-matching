Product Entity Matching

Product entity matching with RoBERTa and comparison features

Compare retailer listings using their text and product fields. The model combines a joint text representation with explicit comparisons of titles, model numbers, brands and prices, and returns a score for each pair.

C+ names the final model in this project: RoBERTa with 42 comparison features, averaged across three training seeds.

01

Task and product inputs

Product matching

The same product can appear under different titles, model-number spellings or incomplete fields at different retailers. Identifying these correspondences helps align catalogues and check duplicate records.

Input and output

The input is a pair of listings with title, brand, description, price, currency, and native model/category fields. The model outputs a match score between 0 and 1; comparing it with the calibration cutoff gives a match or non-match decision.

Data and inputs

Walmart–Amazon product matching data. Business fields and native model/category fields are retained, with separate roles for fitting, epoch selection, calibration and evaluation.

Implementation

Construct 42 comparison features and fuse them with RoBERTa pair representations; compare four reference methods and a separately trained zero-feature control.

Six-stage data preparation and scoring procedure

The final method uses RoBERTa for the paired text and a separate comparison vector for explicit field operations. A title can share many words with another listing while differing in a model digit; a price can be absent or in a different currency. The 42-dimensional comparison vector, named x42 in the code, records those conditions directly. Brand, model, category and title are serialized for RoBERTa, while description and price enter through the feature vector. The 768-dimensional text representation is projected before joining x42. This is the architecture tested in the fixed comparison, not evidence that feature fusion is generally superior: The independently trained C0 control, with all comparison features set to zero, has nearly the same AP on this pool.

03

Field normalization and eight example comparisons

The workbench uses synthetic Acme cordless-drill records and displays normalized fields plus eight selected comparisons from the 42-feature vector. The first scenario changes ZX-100 to ZX100 and brand capitalization while keeping the listing type the same. The second uses ZX101 to expose a model-digit disagreement. The third removes a brand and changes the currency, so presence and price-comparability indicators change.

The listings below are invented teaching inputs. Values are computed by the public feature functions; no RoBERTa call, match label, model probability or identity conclusion is supplied.

Compared with L42, C+ reduces false matches from 35 to 11 while missed matches increase from 23 to 25, improving F1. Its AP is only 0.0381 percentage points above separately trained C0. This comparison does not establish a clear ranking benefit from the 42 features; independent new Walmart–Amazon sample generalization remains untested.

The evaluation is retrospective. The fixed pool’s historical exposure record is incomplete, and performance on an independent new Walmart–Amazon sample has not been tested.
